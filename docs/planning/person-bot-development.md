# Person Agent 执行链路

## 交互与设置

Person 使用账号下的多个具名主会话，复用单聊的侧栏、搜索、消息、输入、问询、授权与流式传输组件。会话 ID 动态生成，新建时由用户命名。上下文可检索同账号的其他 Person 会话，并保留来源会话身份；记忆和 Agent 配置按账号共享。Profile 是模型资源，不决定 Person 账号归属。

设置中可添加执行 Agent，每个预设包含名称、用途、运行时、模型及思考强度。Person 按用途选择预设；至少保存一个 Agent 预设后才能开始聊天和后台执行。原生运行模式复用对应 Agent 的本机凭据，受账号权限控制。

主窗口在任务按钮旁提供工作区选择和扫把清空入口。工作区按账号保存，所有后台子任务统一使用所选目录，已有任务后续执行同样使用此目录；没有选择时统一使用账号的私有工作区。单个子任务不能覆写目录。执行和回流期间禁止切换工作区。扫把经确认后原子清空当前会话的 Person 聊天、目标、执行记录、隐藏任务会话和关联计划；保留其他会话、共享记忆、设置、用量账本与工作区文件。当前会话正在回复、执行任务或回流结果时禁止清空；历史版本检查拒绝过期请求，并同步清除其他窗口的聊天缓存。

主对话只接收精简的预设说明，不注入完整模型目录。模型目录通过设置界面读取；服务端在保存设置和启动执行时检查资源与模型权限。

## 多功能需求拆解与问询

用户的一条描述包含多个功能点时，主 BOT 先提取完整的需求清单，包含明确要求、约束、依赖和完成条件，不遗漏原始要求，也不自行增加范围。同一交付目标下的相关功能点保留为一个任务内的清单；只有可独立交付的目标才分别建任务。依赖按顺序执行，只有相互独立的工作可以并行；对已有工作的补充和修正仍然续接原任务。

派发时向执行 Agent 完整传递适用的清单、约束、依赖和验证要求。执行 Agent 按清单推进并逐项验证；主 BOT 汇报整体完成前，对照实际结果及验证证据检查每一项，明确说明未完成项和阻碍，不能把部分完成说成全部完成。剩余工作只能在已有授权范围内继续。这些是模型提示规则，不新增任务状态或自动验收机制。

缺少的用户输入会实质阻塞工作或改变结果时，主 BOT 必须调用 `bot_decision_request` 并等待回复，不能只在普通回复中留下阻塞问题。常规实现选择由 BOT 自行处理；超时或空回复不代表同意。后台执行 Agent 的问询继续由任务协调器接管。

主 BOT 按实际可用工具和访问权限判断自身能力。无法直接完成时，先通过 `bot_agents_list` 查看执行 Agent 的用途说明及相关分页，以明确用途或已验证能力判断适用性，不能仅凭名称、模型或只有一个／默认预设就认定能够完成。仍然无法确定合适执行 Agent、能力不明确或没有合适人选时，及时通过 `bot_decision_request` 说明具体能力缺口，等待用户指导后再派发受影响的工作，不能盲目选择或逐个试派。

## 后台执行与回流

1. 主会话通过任务工具创建目标，记录发起会话、消息、轮次及有限上下文。
2. 调度器将目标交给独立后台执行会话，按预设运行实际 Agent。主窗口可以继续对话。
3. 子任务问询由任务协调上下文回答；缺少用户意图时，使用主窗口现有问询组件。实际工具授权也使用现有组件。
4. 执行成功后保存结果，自动完成一次性目标。仍有活动或暂停的定时计划时，目标保持开放供后续执行。
5. 持久化回流记录把结果排入任务所属会话的自动唤醒队列。跨会话发起、续聊与定时执行均保留此归属。Person 重新运行，将结果写入并推送到该主窗口。
6. 回流成功才标记已送达；失败可重试，服务重启恢复未送达记录。删除来源会话、关闭目标或替换要求后，旧结果不得重新创建会话或继续推进旧要求。

Person 的未结束执行和待回流结果计入主会话的 `background_pending`，恢复会话时同步返回该数量。前端在首轮回复结束后保持后台监听；主窗口空闲时收到自动运行事件，也会重新注册消息处理器。因此连续对话、刷新重连和定时任务都能实时显示回流结果。

每次回流将执行记录关联到实际写入的主会话回复。回复在 token 用量上方展示任务卡片：左侧为执行 Agent logo，上方为任务标题及与任务列表共用样式的状态标签，下方为可展开的任务描述；点击标题打开该任务的对话抽屉。关联随实时完成事件发送，并按消息读取恢复，因此刷新或加载历史后仍显示在同一条回复上，不会附加到其他轮次。

不存在独立 reviewer、自动返工循环、验收状态或验收按钮。用户在对话里查看结果并提出后续要求，无需点击验收。

## 任务状态与操作

目标复用单聊任务的 `open`、`completed`、`closed` 状态。界面只提供打开与关闭；重新打开不隐式启动执行。运行中，包括排队、等待回答、等待授权以及正在回流时，界面禁用操作，服务端同样拒绝修改。

实际执行状态是 `queued`、`starting`、`running`、`waiting_person`、`waiting_user`、`waiting_approval`、`finished`、`failed`、`stopping`、`interrupted`。用户可以停止任务；停止操作持久化 stopping 意图，等待原生进程确认退出后转为 interrupted。执行失败保留开放目标，并将错误回流主会话。

任务工具支持创建、接管、修改要求、开始、关闭和重新打开。非运行目标可在用户提出后续要求时由 Person 更新并再次执行。定时计划保留独立的启停管理；关闭任务同时取消其计划。

## 任务对话

任务列表直接复用单聊任务抽屉，提供相同搜索、状态筛选和排序，不提供分页操作。点击标题或打开按钮在右侧对话抽屉中展示单聊消息与输入组件，使用任务所属的 `person-task-{taskId}` 会话恢复历史。任务抽屉通过作用域内的聊天 store 独立管理会话、流式订阅和输入草稿，不改变主窗口的当前会话或缓存。Person 主窗口始终保留，抽屉打开时也能继续接收回流。关闭抽屉仅释放任务视图的订阅，不中止后台执行。

后台会话不进入普通 session 列表、搜索、分享或全局活动列表；前端已加载过的任务会话也不会混入单聊列表。仅所属账号可通过任务入口和只读会话接口恢复历史，不能通过普通 socket run、abort、删除消息等操作绕开任务调度。

抽屉中的新消息（含附件）先落入执行记录，再由后台调度器在同一会话继续运行，完成后仍唤醒原 Person 主窗口。已完成目标在发送新消息时自动开放；关闭的目标需手动重新打开。运行中允许发送补充消息，按顺序排队继续执行；停止确认中禁用发送，运行和回流期间禁用任务开关；实际问询、授权仍通过单聊组件回答并同步到持久化交互记录。

## 持久化与边界

- `session_tasks` 保存账号及会话所属目标；Person 目标必须带所属 session_id。
- `person_accounts` 保存账号设置；原生记忆服务使用独立的账号 memory.db，旧 person_memories 表已移除。
- `person_executions`、`person_events`、`person_interactions` 保存实际执行、事件与问询。
- `person_task_origins`、`person_deliveries` 保存发起上下文与结果送达状态。
- `person_task_returns` 将回流回复关联到具体执行，保留该次返回的任务名称和结果状态。
- `person_schedules`、`person_occurrences` 保存定时计划及幂等触发记录。
- `person_operations` 保存用户操作幂等结果。

执行通过租约、generation、要求版本与状态检查屏蔽迟到事件。任务状态操作同时校验账号、revision 和实际运行状态。后台私有会话不出现在普通会话入口，也不能通过其接口读取。

按当前开发环境要求直接删除废弃字段和实现，不维护旧 Person 数据迁移或旧模型选择引用接口。需要重置时仅清空 Person 的目标、执行和对话，保留其他聊天及账号配置。

## 验证

服务端测试覆盖预设与默认继承、后台执行、自动完成、定时重复执行、运行锁定、账号权限、结果回流重试及过期结果屏蔽。浏览器测试覆盖设置、任务打开关闭、运行中禁用、明暗主题、窄屏和三种实时回流场景。

删除会话会取消其定时计划、停止全部任务并等待退出确认，再清理会话及关联执行、问询、回流和索引。其他会话、共享记忆和 Agent 配置保留。旧的无会话目标直接清理，不做迁移或自动接管。
