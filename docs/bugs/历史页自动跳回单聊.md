# Bug 记录：点「历史」约 10 秒后自动跳回「单聊」

> 记录时间：2026-11-05
> 状态：**根因已定位、已在源码修复并重新构建验证通过**；用户当时要求先记录，暂不继续跟进。

---

## 一、现象

在 Hermes Web UI（`http://127.0.0.1:8648`）里，从「单聊」切到「历史」：

1. 页面**能正常跳进历史页**（URL 变成 `#/hermes/history`，紧接着自动打开最近一条历史会话 `#/hermes/history/session/<id>?profile=hunter`）
2. 停留约 **9～14 秒**（不固定，取决于会话列表接口耗时）
3. 然后**自己跳回** `#/hermes/chat`（单聊页，左侧 tab 高亮回到「单聊」）

用户观感：「选择历史老是自动跳到单聊」。

---

## 二、根因（已实证，不是推测）

### 关键代码

`packages/client/src/views/hermes/ChatView.vue`

```ts
// 第 17-20 行：只看 params.sessionId，不看当前是哪条路由
const routeSessionId = computed(() => {
  const value = route.params.sessionId
  return typeof value === 'string' && value.trim() ? value : null
})

// 第 50-55 行（修复前）
async function loadRouteSession() {
  await chatStore.loadSessions(chatStore.sessionProfileFilter, routeSessionId.value)
  if (routeSessionId.value && chatStore.activeSessionId !== routeSessionId.value) {
    await router.replace({ name: 'hermes.chat' })   // ← 就是这一跳
  }
}
```

### 为什么会被弹回去

1. 两条路由**共用同一个 param 名**：
   - 单聊会话页：`/hermes/session/:sessionId`
   - 历史会话页：`/hermes/history/session/:sessionId`
2. 用户在单聊会话页时，`ChatView` 的 `onMounted` 调用了 `loadRouteSession()`，里面 `await chatStore.loadSessions(...)` 是个**慢请求**（实测 9～14 秒）。
3. 用户在这段时间里点了「历史」→ `ChatView` 被卸载，但**那个 await 的 Promise 不会取消**，它还在跑。
4. await 返回后继续执行：此时 `route.params.sessionId` 已经是**历史会话的 id**，而 `chatStore.activeSessionId` 还是单聊那条会话的 id → 两者不相等 → 命中 `router.replace({ name: 'hermes.chat' })`。
5. 于是页面从历史页被强行推回单聊页。

一句话：**已卸载组件的迟到异步逻辑 + 两条路由的 `sessionId` 重名 + 没有做「路由是否已经切走」的检查。**

复现步骤（从会话页切历史、0.15 秒内点击）：**14 秒时跳回**，`performance.timeOrigin` 不变（排除整页重载）。

## 三、修复（已应用）

`packages/client/src/views/hermes/ChatView.vue`，`loadRouteSession()`：

```ts
async function loadRouteSession() {
  const targetSessionId = routeSessionId.value
  const targetRouteName = String(route.name)
  await chatStore.loadSessions(chatStore.sessionProfileFilter, targetSessionId)
  // 等待期间路由可能已经切到历史页：`/hermes/history/session/:sessionId` 与原聊天路由
  // 共用 params.sessionId，此时 routeSessionId 会变成历史会话 id，命中下面的 replace
  // 就会把用户从「历史」弹回「单聊」。路由/目标已变就直接放弃这次跳转。
  if (String(route.name) !== targetRouteName || routeSessionId.value !== targetSessionId) return
  if (targetSessionId && chatStore.activeSessionId !== targetSessionId) {
    await router.replace({ name: 'hermes.chat' })
  }
}
```

思路：进入异步前把「目标会话 id + 当时的路由名」快照下来，await 回来后先比对；路由已经切走（或目标 id 变了）就直接放弃，不再做任何跳转。**只加守卫，不改原有正常跳转语义。**

## 五、遗留 / 以后可以做的

1. **根子还在**：`routeSessionId` 依旧不区分路由名，任何拿到 `params.sessionId` 的地方都可能再踩一次。彻底点的做法是让 `routeSessionId` 只在聊天类路由（`hermes.chat` / `hermes.session` / `desktop.chat` / `hermes.globalAgentSession`）下才有值。
2. **`chatStore.loadSessions` 不可取消**：理想做法是接受 `AbortSignal`，组件 `onUnmounted` 时 abort，避免所有「迟到 Promise 改全局状态」的同类问题。
3. 同类模式可以顺手扫一遍：`HistoryView.vue` 的 `openDefaultHistorySession()`、`ChatPanel.vue` 的会话加载，都存在「await 后直接用 route 状态」的写法。
4. 未提交 git，`dist/` 与备份目录留在工作区，需要时可 `git checkout -- packages/client/src/views/hermes/ChatView.vue` 回滚源码，或用 `dist/client.bak.1793861883` 还原旧前端产物。
